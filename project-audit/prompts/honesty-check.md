# honesty-check.md — 诚实性标注审查 prompt 模板

对抗性审查项目文档中的标记（✅/完成/已闭环/已修复），聚焦一个问题：**这个 ✅ 是否有消费方真实执行证据支撑，还是代理指标虚标？**

## 审查方法

### 1. 收集所有 ✅ 标记

扫描项目状态文件（STATE.md / README.md / CHANGELOG / CLAUDE.md），列出所有声称"已完成/已闭环/已修复"的项。

### 2. 逐条验证：找消费方证据

对每条 ✅：
- **生产环境真执行证据**：有日志/数据/probe mtime 证明在生产中实际运行且产生预期效果？
- **还是代理指标**：仅凭"代码存在""文件注册""test 通过""grep 0 命中"就标 ✅？
- **数据层验证**：如果是数据处理类声明（"已裁决""已去重""已同步"），打开实际数据文件验证

### 3. 诚实边界检查

项目的"诚实边界/诚实标注"习惯是否在本次变更中保持？
- "⚠️ 机制层证据非消费方证据"这类标注是否准确？
- 有没有本该标注诚实边界但直接标 ✅ 的？
- 框架层✅ vs 细节层✅ 是否存在过度宣称？

### 4. 反模式② 复发检测

checklist：
- 测了注册但测了消费吗？
- 测了文件存在但测了内容正确吗？
- 测了 test 层但测了运行态吗？
- 文档宣称数字 vs 实际数据是否一致？
- "代码修了"但生产环境新 hook 还没加载（会话级加载特性）时标了 ✅？

## 输出格式

每个发现：
```
[严重度] 文件:行号 — ✅ 标称 vs 实际
  宣称: <文档说的>
  实际: <真实状态>
  证据: <支撑数据>
  修正: <应该标什么>
```

最后输出**诚实性评分**（1-10）：项目文档的诚实程度，扣分项是虚标✅的数量和严重度。

## 核心判据速查

| ✅ 类型 | 有效证据（可标✅） | 代理指标（不应标✅） |
|--------|-------------------|-------------------|
| 机制注册 | probe mtime + CC 事件触发日志 | hooks.json 有注册条目 |
| 数据产出 | 数据文件内容正确 + 有下游消费方读取 | 数据文件存在 |
| bug 修复 | 生产环境复现 bug 条件 → 不再触发 | test 断言通过 |
| 闭环 | 消费方读取了生产方产出 + 产生了新行为 | 代码链路通 |
