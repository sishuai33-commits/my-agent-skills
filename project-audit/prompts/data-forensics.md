# data-forensics.md — 数据层取证通用指南

对抗性比对项目文档的**数据宣称**与**实际数据文件**。核心问题：文档说的数字/状态，数据文件里真是这样吗？

## 通用步骤

### 1. 识别项目的数据文件

扫描项目 CLAUDE.md / STATE.md 中提到的数据路径，列出所有运行时数据文件（jsonl / json / marker / cursor / log）。

### 2. 提取文档中的宣称

从项目状态文件中提取所有量化宣称：
- 计数类："pending 149 条""experience 158 条""test 95/0/0"
- 状态类："⑤回流通""三源齐""闭环完成"
- 趋势类："持续增长""3 天无停滞"

### 3. 实际数据验证

对每个宣称：
- 计数：`wc -l` / `grep -c` 统计实际值 → 对比宣称值
- 状态：抽样检查数据内容 → 判断质量（字段完整性/重复/异常值）
- 趋势：检查时间戳分布 → 判断是否延续到最近

### 4. 揭露 gap

重点找：
- 宣称值 ≠ 实际值（如 "158 条" 但去重后仅 22 条有效）
- 宣称"完成"但关键字段缺失（如 "⑤回流通"但无 observation_key）
- 宣称"持续"但实际已停滞（如最后更新时间 > 3 天前）
- 宣称"已裁决"但实际裁决为空（status=resolved 但 disposition 缺失）

## 通用数据质量检查项

### 数据完整性
- jsonl 行是否合法 JSON？（`python3 -c "import json; [json.loads(l) for l in open(f)]"`）
- 关键字段是否存在？是否为空？覆盖率？
- 是否有重复条目？去重后有效条目数？

### 数据时效性
- 最新记录时间戳 → 距今多久？
- 时间分布：持续新增 vs 集中爆发后停滞？
- 游标/指针是否在推进？有无倒退？

### 数据结构
- 字段值与文档描述是否一致？（如 `signal_type` 全为 "unknown"）
- 枚举值是否都在预期范围内？
- 嵌套结构是否完整？

### 管道漏斗
```
原始日志 N 条
  → 信号检出 M 条 (比例%)
    → 裁决队列 K 条
      → 有效经验 J 条 (去重后)
        → 实际复用 R 条 (采纳率%)
```

计算每一层的转化率 → 找渗漏点。

## 输出格式

```
## 数据层取证结果

### 1. 宣称 vs 实际 对照表
| 宣称 | 宣称值 | 实际值 | 一致？ |
|------|--------|--------|--------|

### 2. 管道漏斗
（各层转化率 + 渗漏点标注）

### 3. 数据质量缺陷
（按严重度排列：字段缺失/重复膨胀/时效停滞）

### 4. 与文档的一致性判断
- 一致的项 [N 项]
- 矛盾的项 [N 项]  ← 重点
- 文档未披露的数据问题 [N 项]
```

## 注意

本指南是通用模板。具体项目可能需要补充项目特定的数据文件路径和检查项（如 ke 项目有 observations/pending-queue/experience/reuse-log/marker 五类数据文件，见 ke/dev/audit/prompts/ke-data-forensics.md）。
