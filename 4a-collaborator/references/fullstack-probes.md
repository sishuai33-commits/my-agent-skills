# 全栈双向探雷与陌生域补位速查

> 用途：BA/AA 讨论时向下探出可能反杀上层设想的硬约束；遇到陌生业务或技术深水区时快速补位；详设/交付评审期确保软硬件、网络、部署与业务方案不是两张皮。按触发信号查阅，不每轮全扫。

## 一、向上提要求 ↔ 向下探雷触发器

当业务或应用方案里出现左列信号时，主动向下探查中列事项；若底层现实撑不住，按右列及时反杀/收敛上层方案：

| 上层方案出现什么信号 | 必须向下探查的 IA / TA / 硬件 / 网络 / 部署雷 | 踩雷时的反杀与降级思路 |
|---|---|---|
| **实时监测 / 秒级预警 / 自动处置** | 数据采集频次（秒/小时/日）、同步时滞、表计/传感器覆盖率、跨网实时通路、报警误报容忍度 | 收敛为“按日/批次异常线索筛查 + 人工复核”，把“实时监测”标为数据/传感补齐后的远期条件 |
| **多源数据交叉研判**（如水+气+电、空间+业务） | 共同主键或空间编码唯一标识、颗粒度是否对齐（户级 vs 楼栋 vs 台区）、权威源归属、跨委办/企业授权 | 以最小可对齐颗粒度定首期范围；颗粒度不齐的源降为辅助参考或排除在首期承诺外 |
| **垂类模型 / 大模型 + Agent 问诊** | **训练与验证算力 vs 长期运行推理算力**是否同笔预算、并发/时延要求、既有 Agent/工具接口能否复用、真实评测集与专家复核闭环 | 严格拆开“模型验证环境”与“常态化运行环境”归属；既有能力写“优先扩展（待核复用范围）”；先用小样本建独立评测集 |
| **跨委办 / 政企 / 权属单位协同** | 网络安全域隔离（政务外网 / 专网 / 互联网）、数据能否出域、单向光闸或前置机审批周期、核实结果是系统回写还是人工回传 | 区分“离线导出/文件交换”与“在线接口联调”；无依据不画自动回写原系统的箭头 |
| **依托既有平台建设 / 内部工具落地** | 客户平台正式模块归属树、既有能力边界、自研工具在平台内的挂靠位置、部署位置（客户机房 / 政务云 / 私有云）、既有硬件余量 | 先画准“平台包含树”，再逐项标“复用 / 扩展 / 新建”；不把自研产品工具与客户正式模块混在同一层 |
| **采购包边界与业务蓝图错位** | 标内交付物与验收条款、标外前置依赖（数据/环境/关联场景）、谁提供运行资源与专家配合 | 区分“完整业务蓝图叙事”“本期标内交付范围”“标外前置依赖清单（标责任方与到位时间）” |

## 二、陌生域与深水区主动补位（3 分钟补课法）

当用户进入不熟悉的业务域，或触及数据架构、算力配比、网络部署等技术深水区时，按四步输出（全程标注 **`[行业参考/待核估算]`**，绝不冒充本项目已确认事实）：

1. **行业常识框架**：该领域通常怎么跑（核心价值流、关键角色、常见数据对象与痛点），与当前项目的相似/差异点。
2. **关键标尺与估算口径**（必要时联网查最新权威参考）：
   - 算力/硬件类：区分训练（微调/增训）与推理（并发、上下文长度、吞吐/首字时延），给出数量级参考与驱动变量（如参数量、量化方式、峰值并发），标明“需以实测压测为准”。
   - 数据类：给出常见分层/治理步骤（汇聚→对象映射→空间/业务挂接→质量标识→指标/服务）、主数据与权威源常见归属。
   - 网络/部署类：给出政企常见隔离域（接入区/应用区/数据区/训练区）与跨网交换常见路径（API 网关、前置机、离线脱敏包）。
3. **2–3 条差异化探索路线**：明确每条路线的适用前提、软硬件投入量级、干系人接受度、主要风险点。
4. **最值钱的 1–3 个核实问题**：问出能直接决定选哪条路线的事实，替用户省去漫无目的的摸排。

## 三、详设与内部评审期：软硬件“向上挂钩”核对

当方案从 BA/AA 深入到 IA/TA/硬件/网络/部署（如写详细设计、算资源、过内部交付评审）时，做四条双向挂钩检查：

1. **数据挂业务**：每张核心数据清单/治理任务，对应支撑哪条业务闭环或指标？缺失会导致哪个场景降级？
2. **算力与硬件挂应用**：训练算力、评测环境、应用/推理长期运行算力分别对应哪个模块、归属哪笔预算或哪方机房？
3. **网络与部署挂交互**：架构图里每一条跨主体/跨边界的连线，在部署与网络视图里都有对应通路（在线接口 / 前置机 / 人工导入）与安全口径？
4. **资源缺口反写上层**：凡是未落实的硬件、算力、网络权限或外部数据，必须回到上层方案记为“实施前提/待补功课”，不能在业务页假装已经闭环。
