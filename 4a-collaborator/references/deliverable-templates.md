## 一、项目活底座（极简 5 块，跨会话/跨端唯一真源）

项目无既有载体时，在当前场景产出目录维护一份 `方案底座-<场景名>.md`（或直接内嵌在当前活方案框架顶部）。

### 1.1 干系人诉求与价值平衡账

| 干系人/参与方 | 真正想要什么 | 怕什么 / 红线 | 当前方案怎么接住 |
|---|---|---|---|
| 例：业务处室 | 可演示、可落地、有业务抓手 | 只有技术名词、脱离实际数据 | 收缩到单点异常核查闭环 |

### 1.2 事实 · 包装 · 承诺 · 补课账（想 ↔ 讲 隔离层）

| 条目 | 分类（客观事实 / 故事包装 / 本期承诺 / 标外与远期） | 来源或依据 | 若采用该包装，后续需补什么功课 & 现场兜底口径 |
|---|---|---|---|
| 例：完整业务双闭环 | 故事包装（用于讲清机制） | 讨论日期 | 现场明确本期先落模型及验证闭环，完整场景建设归属二期/另议 |

“行业参考/待核估算”单列标注，不冒充客观事实；“故事包装”不冒充“本期承诺”。

### 1.3 归属树与跨层约束账（BA ↔ AA ↔ IA ↔ TA ↔ 硬件/网络/部署）

- **正式归属树**（谁包谁、谁同级，跨页/跨图必须一字不差）：
  ```text
  示例：空感融合平台 > 感知运营中心 > {数据治理工具, 指标工具, 业务问诊Agent}
        空感融合平台 > 空间计算（与感知运营中心同级）
        模型体系（平台外独立） > 智通垂类模型
  ```
- **跨层约束与探雷台账**（前期只记硬约束和雷点，详设期逐项填实并向上指回支撑的模块）：

| 层次 | 已知现实约束 / 支撑项 | 状态（已核 / 待核 / 估算） | 支撑的上层模块或反杀影响 | 责任方/验证方式 |
|---|---|---|---|---|
| IA 数据 | | | | |
| TA 技术 | | | | |
| 算力/硬件 | 训练与长期运行分账 | | | |
| 网络/部署 | 隔离域与数据通路 | | | |

### 1.4 关键设计决定与变更影响

| 决定 | 状态（建议/已接受/被替代） | 依据/前提 | 备选与取舍理由 | 验证方式 | 受影响的模块/页面/交付件 |
|---|---|---|---|---|---|

新事实推翻决定时保留被替代原因，把受影响的旧页面/交付件标为待更新。

### 1.5 项目纠正红线（防复发）

| 原错误 | 正确口径 | 适用范围/来源 | 下次检查点 |
|---|---|---|---|

纠正一次即排查本项目其余材料与页面；跨端继续工作前先读本表。

## 二、汇报生图前：每页轻逻辑约束卡（4A → 生图技能）

每页半屏以内，**只锁边界、归属、关系和文案，不写死像素排版**：

```markdown
### 第 X 页：<标题>
- **受众与主结论**：给谁看；看完能复述的一句话判断
- **范围框**：框内（本期/本标）｜框外（支撑/验证/远期规划）
- **归属树**：谁包含谁；谁与谁同级
- **关键连线**：起点 —[动词/交付物]→ 终点（静态总览写：无连线）
- **准确文案与状态**：关键节点名、核心产出、[建议/待确认/规划] 标注
- **总览锚点**：对应总览页哪个模块（确保命名一致）
```

## 三、交付后轻复盘三栏模板（仅重要交付后或用户要求时触发）

| 归属层 | 本轮沉淀条目 | 来源事实 / 战例 | 动作 |
|---|---|---|---|
| **快层·留本项目底座** | 新核实的干系人/数据/算力/网络事实、新红线 | 本次会议/评审/改图 | 直接写入项目底座 |
| **中层·入跨项目模式/雷区库** | 可跨项目复用的破局招、跨层雷或讲法结构 | 写清：什么局适用 / 为什么有效 / 失效条件 | 用户确认后追加 `references/playbooks/` |
| **慢层·疑似 4A 机制缺口** | 本该由 4A 挡住却靠人工救场的同类返工 | 记录反例与发生次数 | 仅同类反例 ≥ 2 次时才提议迭代主 `SKILL.md` |

## 附录：五件套（启动或碎片梳理时按需选用）
