# 方案设计到汇报生图、PPT 与 HTML 图的交接

> 分工原则：**4A 管“画什么、逻辑边界对不对、整套顺不顺”**；**制图 / PPT / HTML 技能管“怎么画得专业好看、怎么做成可编辑成品”**。根据目标产物选主轨或副轨，不混用两套视觉口径。

---

## 一、主轨：汇报生图 → 看图校准思考 → 成套审稿 → 转可编辑 PPT

适用于对外汇报、客户共创、内部交付评审等需要高视觉质感并最终落成 PPT 的方案页。

### 1.1 发现配套制图 / PPT 技能
优先查找当前项目内现用技能（如项目目录 `skills/solution-slide-production/SKILL.md`）或当前宿主可用的生图 / PPT 技能。读到实际文件后按其视觉规范与工具链路执行；若项目未配备专用制图技能，沿用当前客户/企业汇报视觉参考与本节逻辑交接规范。

### 1.2 生图前交接物：每页轻逻辑约束卡（锁逻辑，不锁版式）
4A 在生图前为每页准备一份半屏以内的**轻逻辑约束卡**（模板见 `deliverable-templates.md`），交给生图环节：
- **受众与主结论**：这页给谁看、读者看完能复述的一句话判断；
- **范围框**：哪些属于本期/本标内，哪些在框外作支撑、验证或远期规划；
- **归属嵌套树**：谁包含谁、谁与谁同级（例如 `平台 > 中心 > 工具`，同级模块显式标明）；
- **关键连线清单**：`起点 → 动词或交付物 → 终点`（仅写有依据的真实关系；静态总览明确写“无连线”）；
- **准确上图文案与状态**：标题、核心节点名、关键输出物，以及“已定 / 建议 / 待确认 / 规划”标记；
- **总览锚点**：本页展开的是总览页里的哪一块，名称必须一字不差。

**刻意不写死的内容**：像素坐标、框宽高、字号像素值、过度细碎的装饰指示——把构图美感、呼吸感和视觉质感留给生图环节发挥。

### 1.3 看图后的反馈分流（支持“借图校准思考”）
用户看图后提出意见，先判断属于哪一类，绝不混为一谈：
- **A. 纯视觉/排版调整**（字密、配色杂、标题层级、想沿用某张参考图质感）：直接交给制图技能局部调图，**显式锁死上一轮已确认的范围、归属树、连线起止与准确文案不漂移**（可用“内容母版 + 风格母版”分工）。
- **B. 看图触发了新的方案思考**（发现全貌写窄、归属关系不对、少了一个闭环或要改受众主线）：**先回到 4A 更新方案底座，算出受影响的其他页面与分工**，再更新对应页的轻逻辑约束卡重新生图。

### 1.4 整套成图逻辑审稿（转 PPT 前必做）
几页图分别定稿后，必须把整套图拼在一起做一次通读检查，只向用户报实际问题：
1. **整套故事线**：从第 1 页读到末页，是否紧扣目标受众？有无重复页或逻辑断层？
2. **跨页锚点与归属**：总览页立出的每个核心块，后页展开时名称、归属和范围边界有没有变味？
3. **事实与幻觉检查**：逐字核查生图中文错字（如把“筛查”写成“筛管”）、偷加的无依据 logo/装饰线、为凑闭环脑补的接收方，以及把“建议/待确认”画成“已建成承诺”。
4. **视觉节奏协查**：与制图技能分工，核对缩略图并排后的标题基线、色温、重点色比例和密度。

### 1.5 转可编辑 PPT 逻辑交接包
需要把定稿图转成可编辑 PowerPoint 时，4A 随定稿图一并交付**逻辑交接包**（直接从底座与约束卡导出）：
- 按页序排列的定稿图路径；
- 每页可复制的**准确正式文案**（免除从位图 OCR 猜错字）；
- 每页**模块归属树**（指导 PPT 对象的分组）；
- 每页**关键连线表（起点 → 标签 → 终点）**（指导连接符端点绑定）。

PPT 重建、原生对象检查、移动模块试改与视觉预览验收由对应 PPT/制图技能完成。

## 二、副轨：单文件 HTML 架构图（调用 `diagram-design`）

适用于探索推演、技术详图、需要轻量源码迭代而不走汇报生图的场景。

### 2.1 发现绘图技能
优先使用当前环境列出的 `diagram-design`。若未列出，按以下本机候选路径查找，读到实际文件后才算已接入：
1. `~/.agents/skills/diagram-design/SKILL.md`
2. `~/.claude/skills/diagram-design/SKILL.md`

相对引用以实际技能目录为基准，不安装、不复制、不修改它的全局样式。若均不存在，简短说明缺失并按 `diagram-methodology.md` 的语义规则直接制作 HTML/SVG，明确为回退路径。

### 2.2 HTML 探索图的默认视觉偏好（仅适用副轨，与华为汇报风分离）
- 默认单文件 HTML（内联 SVG/CSS）、静态、浅色、柔和配色，带克制的 Excalidraw/Obsidian 手绘感；中文保持清晰，不对文本施加抖动滤镜。读 `primitive-sketchy.md` 取适合当前密度的形状处理。
- 在当前产物中设局部 token，不修改 `diagram-design/references/style-guide.md`：纸色 `#faf9f6`、文字 `#28343b`、蓝 `#527991`、绿 `#62836d`，警示用低饱和红并附文字。
- **与 `diagram-methodology.md` §9 的口径统一**：单张浅色探索图优先沿用上述柔和色板；仅在跨 4A 四视图并列需要区分域归属时，采用近似柔和色阶对应 BA/IA/AA/TA，并用标签和形状做冗余。
- 中文使用系统字体回退，不依赖外链字体；默认只出所需版本，不自动补深色版或 PNG。

### 2.3 HTML 语义口径与实际验收
- 架构内容、项目决定和用户要求优先于绘图示例；不为了节点预算删除影响结论的责任、依赖或失败路径。
- 容器嵌套表达包含关系，静态能力图不强加连线；不把置信度、异步消息、返回消息、信任边界全画成同一种虚线。
- 验收顺序：①对照约束卡回读节点、关系与状态；②运行实际存在的 `scripts/self_check.py`（未安装的仓库脚本不假称运行）；③用可用浏览器打开实看中文换行、截字、穿线与缩放可读性；无渲染能力时明确说明“尚未完成视觉验证”。
