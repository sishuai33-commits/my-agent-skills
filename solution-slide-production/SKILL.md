# 方案汇报制图与可编辑 PPT

专注**视觉表达、版式构图、多页风格统一和可编辑 PowerPoint 重建**。实际生图和 PPT 制作使用当前宿主对应工具。

## 与 4a-collaborator 的交接边界

- **优先接收 4A 的轻逻辑约束卡**：每页若已有 `4a-collaborator` 给出的受众与主结论、范围框、归属树、关键连线起止、准确文案与总览锚点，**将其作为本轮生图/改图的硬约束**，视觉构图、模块比例、留白与层次自由发挥。
- **无 4A 约束卡时轻量补齐再画**：只有零散讨论稿且本轮未跑 4A 时，先用几行文字对准受众、每页一句判断、归属包含与真实连线，删去对话痕迹、同义复述和过程话，不把聊天原文直接堆上画布；材料未写明去向的箭尾/接收方绝不为凑闭环脑补。
- **看图后的反馈分流（关键）**：
  - 用户指出**视觉/排版/质感问题**（字密、配色杂、傻大、沿用某张参考图质感）→ 在本技能内局部调图，同时**锁死已确认的范围框、归属树、连线起止与文案不漂移**。
  - 用户看图触发**方案思考、边界、归属或整套页序调整**（“全貌写窄了”“这两个归属不对”“6 页太散”）→ **先回 `4a-collaborator` 更新方案底座并标出受影响页面**，拿到更新后的约束卡再重绘，不在生图提示词里硬打补丁。

## 让版式服务内容与关系

| 本页要表达的重点 | 优先采用的构图手法 | 视觉核对 |
| --- | --- | --- |
| 交付范围与落点 | 用共同外框圈住本期范围，应用落点放在框外对应位置；需要时用右窄栏补充图外核验要求 | 一眼能否分清框内本期、框外支撑/验证？ |
| 业务主线与交接 | 依动作与交接排主线，每步留出明确产出区，双回路分开走线不穿字 | 能否沿主线看出下一环节拿什么继续工作？ |
| 静态整体架构 | 用分层和嵌套画归属、并排画同级；总览克制连线，避免箭线丛林 | 嵌套关系是否和归属树一字不差？ |
| 模块机制与调用 | 区分模块、动作与产出，主调用与反馈走清晰留白通道，线旁短标动词+对象 | 每条线端点落位是否准确、无斜线穿框？ |

“左主图、右说明”适合解释交付边界，右侧只放图外增量信息；承接关系自下而上时采用上下分层。构图随页型变化，不把所有页画成同一种格子。

## 出图和调图

1. **优先跟随当前客户/项目视觉样图**：优先采用当前客户模板、项目既有视觉规范或用户在本套材料中称赞的成图，标明每张参考图提供的视觉依据。需要通用调图翻译表与指令模板时，打开[调图翻译与生图指令](references/image-direction.md)。
2. **可选内置风格预设**：当缺少新样图、且希望采用华为工作汇报质感时，按需读取内置预设[华为汇报风视觉预设](references/presets/huawei-report.md)及其样图（仅迁移白底、红题、浅灰分区、细线和比例等视觉特征，绝不迁移样图中的项目名称与业务内容）。
3. **视觉焦点与密度控制**：采用内置华为汇报风预设时，通常以 16∶9 纯白底、左上红色主标题、深色中文无衬线正文、浅银灰分区和细边为起点；若采用其他客户体系则按其配色与字体基准执行。每页选择一个业务焦点，把主要强调色用于交接、边界或要讲的能力。用宽扁比例、对齐、段间距与文字层级改善密度。图标、数字、辅助色与轻投影跟随本套参考和当页用途。放大标题、全铺灰框或增加强调色面积都会改变阅读重心，改后须看实际缩略图。
4. **生图指令与母版分工**：生图指令写出本页判断、准确上图文字、范围与归属约束、主视觉、参考图各自用途和本轮需保留的内容；不写死僵硬像素坐标。已有明确参考时将实图随指令交给工具。生成后读图逐字核对中文、数字、箭头、归属边界、多余 logo 和被挤掉的信息。需要改图时，在“内容母版”和“风格母版”之间明确分工，两者可以取自不同版本。
5. **成套节奏与逻辑通读**：风格尚在探索且后页依赖总览时，先做有代表性的页。用户接受方向或已要求连续生成，就按同一参考逐页完成，再把缩略图并排检查标题基线、色彩、线重、密度与节奏，并配合 4A 做整套逻辑通读（锚点一致、无错字、无越界承诺）。

若用户后续要转可编辑 PPT 且本轮未通过 4A 产出交接包，在交付说明中按页留一份短记录（页序、所选定稿图版、准确文案、归属树、关键连线起止与配色语义），供转制直接复用。

## 用定稿图转 PPT

“把这些图放进 PPT”按源顺序等比入页；“可编辑、要继续改、可调模块或连线”按定稿图 + 4A 逻辑交接包重建原生对象。用户从一开始就明确只要可编辑稿且模板足够时，可直接制作原生页。

- 转制前以 4A 逻辑交接包（或正式底稿）校准全部文案、归属分组和连线起止，不再靠位图猜字；疑似错字对照正式底稿，仍有歧义则保留原词并在交付说明中点出。按同一套基准微调标题位置、字号、线重、圆角和间距。
- 让需维护的标题、正文、模块、关系线和图表能分别修改。按归属单元合理组合，需随模块移动的线优先绑定端点。照片或复杂插画可保留为图片；示意曲线没有原始数据时，保留其示意性质。用图片作背景时检查有无重复文字或遮住的旧版对象。
- 导出后逐页查看实际渲染，与定稿图对照主次、中文换行、边界和箭头。再在副本中对代表页实际试改一句较长文字、移动一个模块，检查溢出与连线。运行[PPTX 对象检查](scripts/inspect_pptx.py)定位需要重点检查的页时，**按当前加载的 `SKILL.md` 解析出的真源目录拼接脚本路径（绝不依赖当前工作目录 `cwd`）**；共享真源可直接运行：
  `python3 /Users/sishuai/Documents/My_Skills_Library/技能库_自建/solution-slide-production/scripts/inspect_pptx.py "文件路径.pptx"`。文件结构、渲染结果和实际编辑分别报告。
- 将用户需要的 PPT 及可直接看的预览交付到指定位置。可编辑稿的说明要具体到哪些元素能改、有哪些保留为图片，以及有哪些编辑动作实际测过。
