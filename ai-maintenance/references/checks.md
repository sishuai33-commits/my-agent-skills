# 检查要点

按本轮范围选用。下列方法自包含，不要求安装或调用其他技能。

## 入口、来源与生效范围

检查全局与项目指令、技能主文件及实际引用、Agent 定义、命令入口、工具与 hook 的相关配置。先核对宿主实际发现方式和加载条件，避免把目录中的历史文件当成活动规则。

共享链接记录入口和解析后原件；区分同一源被多端消费、独立副本漂移以及同名覆盖。报告共享影响，保留停用资产，不能因查到旧文件就重新激活。引用缺失先区分占位、运行生成、外部依赖与真实断链。

## 指令、提示词与技能

| 问题 | 如何核对 |
|---|---|
| 同一事项两套相反要求 | 并列引用两处原文，检查优先级、目录范围、宿主和明确例外，再判断是否真正冲突 |
| 旧模型补丁或强制流程 | 找到原失败与当前目的；模型换代只构成复查信号，是否删除由当前证据决定 |
| 临时事故变成永久规则 | 核对适用场景，能缩为局部约束就不保留全局触发 |
| 触发过宽或路由重叠 | 用正例、邻近但无关的请求检查实际路由；格式词、产品名不能独自决定写入目标 |
| 文档说工具不可用或必须走固定端 | 核对当前宿主工具、插件和授权；保留真实限制，纠正跨端外推 |
| 改了主文件仍行为冲突 | 追到本轮实际引用的参考文件、旧命令、Agent 和默认输出要求 |
| 技能是否落后上游 | 跑 `技能库_自建/skills-management/scripts/skills-check.sh`：A 组仅 fetch 成功后判断当前落后数，离线 CACHED 与网络失败 UNKNOWN 不算同步；B 组按 `UPSTREAM.md` 同时核版本（如有）和 sha256，缺基准为 UNKNOWN；C 组缺档案同为未知。退出码 0=全部可核无变、2=有更新、3=含未知、1=自身错误；更新+未知返回 3 并保留双标识 |

工具参数语义、失败条件和必要格式通常要保留。合法重复可以增强上下文独立性；只有存在矛盾、误触发或实际维护问题时才建议合并。审计也检查本维护技能，不能因为它是检查者就免检。

## 工具、命令与配置

路径和本地命令先从源码、安装清单及已知帮助文档核对；安全、无外部副作用的版本或发现查询可按授权执行。执行未知脚本、登录、安装、真实 hook 及外部模型测试要先识别副作用，审计不等于允许运行文件里列出的所有命令。

配置检查只取与问题相关的字段，例如启用状态、路径和工具名称；不输出凭据、完整环境、敏感请求头或整个配置。某个命令字符串可能含密钥，展示前先遮蔽。hook“已注册”与真实事件“已触发”分别记录，不手工补跑来冒充原生触发。

涉及 API、版本或厂商行为变化时查当前官方说明并记录适用对象；本地版本固定且源码足以解释的问题，可依当前代码判断。按故障影响确定修复范围，不将安装时间或版本号作为自动升级依据。

## 历史、接续与状态

上轮报告、现有记忆和用户纠正均可用；任何一项缺失都不阻止当前检查。长摘要中用到的关键结论回读原始依据，旧授权不随历史材料自动扩展。

同一问题的旧失败保留。旧报告说“待处理”而本轮已修，应以版本和验证证据更新已有记录；只读审计只报告这种差异，不主动改知识库。保留哪些环境、真实业务和运行生命周期尚未覆盖。

## 方法来源与边界

设计参考了既有 claude-api 的 prompt-audit（定位证据、区分过时内容与必要约束、提出可评审修改）和本地 2026-10-02、2026-10-10 的审计经验。这里独立表述跨端通用方法；没有导入其特定模型假设、固定审计阵容或运行时依赖。后续依据真实维护结果更新本技能，不自动跟随其他技能升级。
